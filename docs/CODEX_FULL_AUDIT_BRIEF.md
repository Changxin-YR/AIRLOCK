## 3. 四个项目目标与四条架构原则

### 项目目标

- **G1**｜个人项目：本地或少量容器可运行，依赖与成本明确；不虚构团队、生产部署、商业用户或个人独立手写贡献。
- **G2**｜简历价值：可复现演示、真实代码路径、可靠测试与技术取舍能支撑简历；每条简历主张能定位代码和证据。
- **G3**｜创新表达：聚焦“影响证据＋服务端执行绑定＋审批体验/疲劳治理”的工程组合；核对竞品公开资料，不宣称所有开源只有两态或无人做过 HITL。
- **G4**｜面试能力：交付与最终代码一致的问题、标准答案、追问、演示步骤和限制说明；用户能解释正常路径、失败路径及替代方案，而不是只记关键词。

### 架构原则

- **A1**｜Fail-closed：权限、策略、必需预演或执行条件不能可靠确认时，不发生未经授权副作用。崩溃、超时、模型异常、审计异常和恢复路径都要验证。
- **A2**｜服务端持有决策权：身份来自服务端认证，审批绑定动作对象；Agent 没有目标直连权限或 reviewer 凭据。客户端 supplied approved/risk/principal 无授权效力。
- **A3**｜代理自身可观测：请求、策略、预演、审批、执行、审计和错误能关联；日志脱敏且故障可定位，不能靠吞异常显示成功。
- **A4**｜诚实处理未知影响：精确、估算、未知分别表示并说明来源和覆盖范围；无依据的备份时间、可逆性和影响数字禁止显示为事实。必需预演失败不等于获准改用猜测执行。

## 4. C1—C12 原始能力：逐点核查、补齐和复验

每个 C 项既要有总行，也要有下列子项。不能只给 C 项一个含糊的“部分完成”。当能力只支持部分工具/传输/数据库时，列出支持矩阵和未覆盖部分；小范围用例通过不能证明无边界的“通用”。

### C1 透明代理接入：协议无关核心、MCP＋HTTP

- **C1.1**｜核心协议解耦：审批/策略/执行核心不依赖某个 Agent 框架。定义清晰的工具请求、影响预览、执行收据和状态接口，HTTP 与 MCP 共用核心安全逻辑。
- **C1.2**｜真实双入口：HTTP 调用和官方 MCP SDK 初始化、发现、调用、拒绝、pending、状态查询、错误传播都实际运行；分别记录传输、SDK、规范和客户端版本。
- **C1.3**｜透明接入真实性：核验是否代理真实上游工具，而不是仅暴露 sql_execute/action_status。增量实现配置驱动、allowlist 限定的上游工具注册/适配路径，至少完成一个独立上游测试服务的受控端到端调用；它不能替代真实第三方/LLM 客户端验证。对原“零改造”分别报告无需改业务代码、需要改配置、需要适配异步等待这三种情形。
- **C1.4**｜等待与版本兼容：根据实际采用的官方规范核对长任务/Tasks 等能力；不以“MCP 根本不支持长任务”作为事实。客户端不支持异步能力时使用有文档的回执/查询方式，pending 不能表示执行成功。不为“透明”无限保持请求连接或伪造结果。
- **C1.5**｜接入安全：注册上游的配置由受信操作者控制，不允许 Agent 传任意 URL、命令或凭据变成开放代理。检查 SSRF、重定向、越权工具发现、token audience（适用时）、凭据隔离和上游错误脱敏；禁止把入站凭据未经正确授权地透传下游。

### C2 三态策略引擎：CEL＋YAML

- **C2.1**｜三态契约：固定 pass/block/need_approval 的语义、优先级和错误处理。身份认证、资源权限、硬性禁止不能被后续规则或模型覆盖；原有“所有支持写入需审批”不能被默默放宽。
- **C2.2**｜真实配置引擎：实现安全 YAML 加载、schema 校验、规则 ID、CEL 表达式解析/类型检查及受限求值；不能使用 Python eval 或普通 if 冒充 CEL。记录所用实现、版本、能力限制和资源上限。
- **C2.3**｜版本与变更：策略变更有版本/内容摘要；无效配置拒绝激活并保持已验证策略，不默默放开；策略变化后的旧 pending 必须重新验证或失效。缓存不能跨策略版本误用。
- **C2.4**｜规则对抗：补规则冲突、缺字段、类型错误、unknown、恶意配置、表达式过大/过慢、规则重载并发等测试；未知结果不能按 false/pass 处理。
- **C2.5**｜兼容性说明：提供可运行策略示例和测试。使用 CEL 不等于与 Envoy 的变量环境、函数、优先级和错误语义全部兼容；“与 Envoy 对齐”必须有明确子集及兼容测试，否则记为未验证。

### C3 影响范围／爆炸半径计算

- **C3.1**｜隔离预演：SQLite 克隆和预演必须不改变真实目标；断言目标内容/指纹和行数不变，不能只检查返回值。预演失败、超时、资源耗尽时验证阻断路径。
- **C3.2**｜真实影响：区分命中行、发生变化行、返回行和字段差异；处理零变化、RETURNING、触发器/级联、NULL、二进制、排序和采样。未支持的模式明确拒绝或未知，不报告伪精确值。
- **C3.3**｜证据化展示：影响快照保存来源、生成时间、目标身份/模式版本、数据版本或指纹、样本范围、截断标记、exact/estimate/unknown 与限制。关键总数不能用样本数替代。
- **C3.4**｜执行绑定：审批对象绑定规范化请求、参数、工具与目标、策略、影响快照及有效期；执行前验证数据/条件漂移。必须在不可被其他写入穿插的事务或适配器等价机制内做最终检查。
- **C3.5**｜能力边界：列出各适配器支持的 dry-run 范围。不能把 SQLite ROLLBACK 称为通用 Shell/外部服务沙箱；无安全隔离的操作不实际执行。“估算降级”只是信息能力下降，不是授权降级。

### C4 可逆性判定、恢复建议与回滚方案

- **C4.1**｜拆分概念：分别建模技术可逆性、恢复可行性、恢复证据和业务授权。预演回滚、事务提交前回滚、提交后补偿/恢复必须在 UI 和报告中区分。
- **C4.2**｜恢复依据：备份存在与时间必须来源于实际验证；没有依据显示 unknown。LLM 文字建议、保留了部分 diff 或执行过一次备份命令，都不等于恢复已经验证。
- **C4.3**｜可运行恢复切片：对安全支持的合成 SQL 场景实现明确范围的回滚计划/补偿方案，在隔离副本演练并核对内容、约束和审计。若不能实现，给出具体缺口，不能以事务 ROLLBACK 标此项完成。
- **C4.4**｜恢复也是副作用：提交后的补偿是新动作，需独立权限/审批、版本校验、幂等及审计；有后续写入时不能盲目覆盖。补偿失败/结果未知也要有收据与处理流程。
- **C4.5**｜安全修正：不实现“仅因可逆就静默放行”。自动 pass 必须有独立、服务端预先授权的策略；原默认所有写审批保持不变。不可逆操作永不通过学习自动降级，硬性禁止操作不能靠人点同意解除。

### C5 静态规则＋LLM 语义风险评估

- **C5.1**｜可插拔实现：保留无需 API key 的确定性评估器；实现真实 provider 的可选语义评估路径、结构化 schema、超时、并发/费用上限。不能只写一个 MockLLM 就宣称真实接入完成。
- **C5.2**｜权限边界：模型只能提供受限风险建议，不持有审批、直写数据库或执行 shell 的权力；模型不能覆盖硬拒绝、身份、数据范围和人工审批要求。LLM 输出必须被 schema 和服务端约束再次验证。
- **C5.3**｜对抗与故障：测试命令伪装、注释、Unicode/大小写、提示注入、伪造系统消息、无效 JSON、缺字段、越界分数、超时和限流。无效模型结果按明确 fail-closed 规则处理，不自动降为低风险。
- **C5.4**｜缓存与成本：区分 provider prompt cache 与应用层结果缓存；缓存键包含模型/提示模板/策略/工具参数及访问范围，涉及快照时包含数据版本。记录命中与失效，不跨权限范围复用敏感内容。
- **C5.5**｜真实验证分账：离线契约测试、仿真响应和真实模型调用单列。只在存在本项目明确授权的凭据、供应商和预算时运行真实测试，记录模型版本、usage、调用 ID 和脱敏证据；否则 live 项为 BLOCKED_EXTERNAL，成本为 unknown/null 而不是虚构为 0。

### C6 审批编排、路由和超时

- **C6.1**｜持久化状态机：定义创建、pending、批准/拒绝、过期、执行中、成功、失败、结果未知等业务状态及允许转换；具体名字可适配现有实现，但不得将批准、已执行和成功混为一谈。
- **C6.2**｜独立身份与路由：实现最小可维护的 reviewer 配置和按工具/资源/风险路由；至少用两个独立 reviewer 身份验证授权范围、路由缺失、越权查看/审批和身份撤销。不要求因此先造 SSO 或复杂多租户系统。
- **C6.3**｜TTL 与通知：审批有效期由服务端判定，并考虑服务重启与时钟偏差的处理；SSE 只通知不授予权限。验证断线、重连、重复事件、客户端关闭/伪造消息、过期边界和服务重启；不能依赖浏览器倒计时保证安全。
- **C6.4**｜并发/幂等：同键同内容返回原收据，同键不同内容冲突；批准/拒绝竞争、重复提交和 worker 重试不产生重复副作用。响应丢失后先查原 action，不能换键盲重试。
- **C6.5**｜崩溃与远端效果：当前单库业务效果、终态、审计验证原子性。新增远端工具时显式处理 outbox/执行租约或等价机制、目标幂等收据、结果未知与对账；不能靠本地事务声称分布式 exactly-once。

### C7 知情审批界面：diff-first 与真实用户路径

- **C7.1**｜信息层级：先呈现“谁要对什么做什么、影响多大、是否可恢复、为何需审批”，再显示原始命令和详细 JSON。提供数量、变化前后对照、估算/未知/截断提示、范围与过期信息。
- **C7.2**｜完整交互：实际跑通凭据接入、队列、详情、批准、拒绝、过期、失效、执行失败/未知、历史、审计、退出。高风险动作有匹配当前快照的确认，阻止误触/重复提交，错误可读且能安全恢复操作。
- **C7.3**｜前后端一致性：状态、权限、数量来自真实 API，不能用静态 JSON 冒充业务；刷新/切页不能覆盖用户正在填写的审批表单或展示别的 action。服务端先筛 pending 再分页，新增 105 条只读历史后旧 pending 仍可找到。
- **C7.4**｜原生浏览器与安全：桌面和移动端实际运行、截图并检查；测试长中文、长 SQL、空/加载/失败状态、键盘焦点、标签和文本溢出。非可信数据按文本渲染，审查 XSS、CSRF（会话适用时）、CORS、凭据 URL/日志泄露及退出清理。
- **C7.5**｜埋点真实：使用首次可见而非仅 mount 作为计时入口，结合 IntersectionObserver、页面可见性与单调时钟记录前台可见时长；定义重复曝光/返回页面/后台暂停口径。客户端遥测不得参与授权，也不等于真人已经理解风险。
- **C7.6**｜可用性结论：为新操作者提供简洁使用说明、角色区别和演示数据警告；检查无 key/offline 体验。自动截图只能证明所测界面，不得凭截图宣称“3 秒正确决策”或全面可访问性认证。

### C8 审批疲劳治理：不可被幂等或限流替代

- **C8.1**｜相似请求归并：实现明确分组规则，例如同申请人/权限范围、同资源/工具、同策略版本、有限时间窗；显示每个成员和累计影响。零权限、不同目标或风险不相容的请求不能混成一组。
- **C8.2**｜批量决策安全：可批的组绑定成员 ID、请求摘要、快照、策略、TTL 和 group digest；新成员加入、成员漂移/过期时重新确认。逐成员执行前校验并给出收据；不能批准隐藏成员，也不能把多项低风险累计成高风险而仍自动放行。
- **C8.3**｜风险预算：实现可解释、可配置的预算单位、作用域、时间窗、累计/预占/结算、并发一致性和恢复规则。重启/多 worker 不能重置绕过；只换 action ID 不能重获预算。预算是策略限额，不是已证明的事故概率上界；预算不是额外授权，高危/不可逆不能因“还有额度”免审。
- **C8.4**｜学习型治理的安全版本：从历史决策生成可解释建议，先 shadow mode，不自动学习越权。建议生效需受信操作者显式批准、版本化、限定范围/期限且可撤回；模型投毒或反复申请不能解锁高危操作。保留“原自动降级目标已作安全修正”的记录。
- **C8.5**｜效果区分：分别测只读免审率、重复抑制率、相似请求折叠率、实际批量审批率及审批错误。不能用请求幂等、队列上限或隐藏消息冒充完整疲劳治理；必须保持相同任务完成质量再比较审批数量。

### C9 结构化拒绝与 Agent 安全改道

- **C9.1**｜拒绝协议：返回 action_id、稳定 reason_code、安全说明、是否可重试及允许的替代方向；不得暴露密钥、内部路径、精确可被探测滥用的策略细节。
- **C9.2**｜模拟演示：真实拒绝一个合成删除请求，验证目标保持不变，再由模拟 Agent 依据结构化结果走 SELECT/缩小范围等安全路径；不是只打印一句“已改道”。
- **C9.3**｜真实 Agent 验证：使用明确授权的真实 host/模型完成提交、等待、批准继续和拒绝后改道，保存真实工具轨迹。无授权凭据则此项受阻；模型不得自动批准自己的请求或伪造完成结果。
- **C9.4**｜有界恢复：定义拒绝、超时、无权限、结果未知等情况的不同重试规则；设置最大重试次数，验证不会无限换键、伪造数据或绕开代理。不要把某次真实事故的成因未经证据归因于“缺少结构化拒绝”。

### C10 全量审计与回放

- **C10.1**｜原始审批证据：保留当时实际呈现的请求/参数/影响/策略/模板版本、review digest、身份、时间、决定与理由、执行收据和相关 ID；不是事后重算的另一份快照。
- **C10.2**｜完整性：测试 HMAC/链验证对篡改、插入、重排和动作归属替换的检测；检查 seq/action 绑定、密钥轮换策略及读审计的权限。无外部锚点时不能声称可证明尾部未删除或抵抗服务器和密钥一起失陷。
- **C10.3**｜失败与隐私：审计失败不能导致静默成功；验证业务/终态/审计的一致性。保留必要证据同时脱敏，限制 SQL 样本、凭据和个人数据的查看/导出范围。
- **C10.4**｜回放定义：回放是按原快照重现决策过程，不是重执行副作用。报告明确外部不可变存证是否存在；它可作为后续增强，但没实现不能宣传对应保证。

### C11 评测、回归与 CI

- **C11.1**｜多层自动测试：包含单元、接口、数据库真实效果、授权/并发/崩溃反例、官方 MCP SDK、原生浏览器和真实 Docker。测试观察效果、终态与审计三者，不能只断言 HTTP 200。
- **C11.2**｜数据与消融：按后文 B1—B8 实现可复现实验管线、分组拆分、独立基线、逐样例结果和误报/漏报。没有真实来源或标签时不伪造，也不把作者规则一致性当真实风险识别效果。
- **C11.3**｜CI 门禁真实性：记录真实子进程退出码、命令、JUnit 和必需产物；验证故意失败时 CI 必须失败。禁止无 pipefail 的吞错管道、|| true、删断言/skip 必测项、把 mock 模式当真实运行。
- **C11.4**｜回归门槛：安全不变量零失败；对固定回归集的质量退化设显式门槛。性能按冻结环境和口径评价，不因 CI 抖动偷偷改目标。阈值未达要报告，不能仅展示好看的子集。

### C12 可观测、延迟、token 成本与缓存看板

- **C12.1**｜端到端关联：建立 request_id/action_id/trace_id 的关系，覆盖接入、策略、预演、审批、执行、审计；异步恢复仍可关联。跨进程/上游追踪与本地日志分别标明实际支持程度。
- **C12.2**｜真实指标：展示请求与三态分布、排队/过期、各阶段 p50/p95/p99、失败、预演覆盖率、缓存命中/失效、模型 token usage 和成本。没有数据显示“尚无数据”，不填假曲线。
- **C12.3**｜费用口径：实际 usage 与估算分开；价格表记录来源、模型、币种和生效时间，未知价为 null。区分输入、输出、cache read/write 及供应商差异；统计可与脱敏账单/usage 对账，不用默认 0 掩盖缺失。
- **C12.4**｜可观测安全与开销：权限保护指标和追踪，脱敏日志；防止以 SQL/参数/用户输入作无限基数标签。测试监控导出故障不会赋予权限，也不会掩盖关键审计故障；测量开销并说明边界。

## 5. L0 功能验收：七项真实闭环

- **L0-1**｜接入实际客户端：SDK 互通、模拟器和真实模型 Agent 分列；真实 Agent 项需真实 host/模型轨迹，不可由模拟器代替。
- **L0-2**｜真正暂停副作用：请求进入 pending 后目标未变化，原影响快照可查看；关闭浏览器或客户端断线不影响服务端控制。
- **L0-3**｜独立批准后继续：合法 reviewer 批准正确对象，执行符合快照/策略，Agent 能获得最终真实结果；重复查询/批准不重复执行。
- **L0-4**｜超时默认不执行：审批超时、连接超时和执行结果未知分清；未知不能当成功，也不能盲重试可能已发生的远端效果。
- **L0-5**｜崩溃与恢复安全：pending 重启不自执行；提交前崩溃回滚；提交后响应丢失可查收据；已删除合成数据重启不会自动重新播种伪装恢复。
- **L0-6**｜拒绝与安全替代：拒绝后目标不变、原因结构化、有界安全改道；模拟和真实模型各有相应证据。
- **L0-7**｜审计字段完整：逐状态检查必需字段与原始快照，完整率目标 100%；有正当理由不适用的字段需 schema 明确允许并记录原因，不能统一填空蒙混。

## 6. L1 技术指标：原目标保留，测量口径先冻结

下列是原始目标，不是当前已达到的成绩。建立指标登记表，预先固定样本、单位、统计窗口、计时边界、排除规则和置信区间方法。

- **T1**｜危险操作召回率目标 ≥90%。先定义“危险”的独立业务金标、权限上下文和模型/规则预测阈值；TP/(TP+FN)，同时给分母、漏报样例和覆盖范围。危险语义识别召回与危险请求被阻断/送审的保护覆盖率分别报告，不能把所有写操作都定义为危险，或把“全部写必审”带来的保护覆盖率冒称语义识别能力。
- **T2**｜误报率 FPR 目标 ≤10%。在同一冻结总体中，分别报告风险分类器对非危险样本的 FPR，以及策略执行器对金标应 pass 的合法请求的额外拦截/送审率，均明确 FP/(FP+TN) 的具体金标和分母。二者不能混名；与 T1 的风险分类召回成对报告，并另报三态混淆矩阵、拒绝/需审细分、未知和不支持占比，不能挑选不同子集美化结果。
- **T3**｜静态路径判定 p95 <300ms。明确包括与不包括的工作，使用稳定时钟；记录样本量、冷/热启动、并发、错误、系统/依赖版本，不把单个函数耗时当请求整体耗时。
- **T4**｜dry-run 路径 p95 <5s。记录数据规模、操作类型、复制/执行/差异计算边界及超时率；不能删除慢请求后重新计算漂亮 p95。
- **T5**｜可评估影响估算相对偏差目标 ≤±5%。逐例给独立真实值与估算；真实值为 0 单列绝对误差和误判例，不除零。精确模式要求所声明计数/差异真实一致；unknown 不混入已通过分母，另报覆盖率。
- **T6**｜放行路径延迟增量目标 <100ms。原设想未指明统计量，本轮预注册以 p95 为验收量并另报均值。相同合法只读负载对照直接调用工具与经代理调用，随机交替/重复运行，说明端到端和配对增量定义；不能把两个无关 p95 相减冒充配对 p95。

共同要求：保留原始计时记录和脚本，明确端到端是否包含认证、持久化、提交、网络与排队；人工等待另计。内部策略函数、HTTP E2E 和真实上游 E2E 分别报告。小合成库结论不能外推生产规模。未满足目标就是未满足，不改数字来通过。

## 7. Benchmark：数据来源、标注和消融

- **B1**｜来源覆盖：至少 200 例起步，并分别提供公开真实事故的可追溯重建、用户明确授权且脱敏的日常 Agent 日志、手工合成对抗样本。每类记录来源/授权/局限及数量；缺少真实来源时真实来源项不通过，不能把同一合成模板换名字补足。
- **B2**｜核心金标：至少 expected_decision、risk_level、impact_ground_truth、reversibility 四类标注；增加必要的任务授权上下文、case_id、来源类型、原始出处、工具/适配器、数据快照、family_id、split 和标注依据。未知字段保留 unknown，不强填伪精确值。
- **B3**｜双人独立标注：两名真实标注者独立标注，记录分歧和仲裁；Cohen's κ 目标 ≥0.75，报告适用的标签字段、样本量和不确定性。两个模型、两个提示词或同一人标两遍不等于双人；未完成时标 BLOCKED_EXTERNAL 并交付标注模板/导入工具。
- **B4**｜防数据泄漏：按事故/语义模板族/相近来源分组拆 dev/test，可采用历史 6:4；冻结哈希。tuning 模式不得读 test。公开旧 test 在反复观察后只作回归，不冒称全新盲测；增加新的保留集或独立外部评估并如实标记独立性。
- **B5**｜四组独立消融：朴素关键词基线、纯 LLM、混合、混合＋dry-run。关键词基线独立实现，不能用混合代码关闭开关冒充独立基线；固定输入、任务、数据、模型、提示与计时口径。纯 LLM 的测试不得连接可造成真实损失的执行端。
- **B6**｜结果管线：输出逐例预测/金标/原因/时延/影响误差、整体与各来源/工具分层的混淆矩阵、召回/FPR、覆盖率及成本。缺真实模型时相应两/三行不执行或受阻，不能让规则结果顶替 LLM 消融。
- **B7**｜可复现与门禁：固定随机种子、版本和参数，测试计算公式、边界、空集/缺失/分母，使用独立小样例核对结果；真实效果 ground truth 不调用被测实现自己的同一 helper 来生成。
- **B8**｜负结果与声明：混合不优于规则、误报升高、dry-run 慢或覆盖不足均保留；合成策略一致性、真实危险识别和生产安全分别命名，禁止凭作者合成集高分得出普适结论。

## 8. L2 真人体验实验：目标与可执行实验工具

先实现 A/B 实验所需界面、任务导入、事件记录和分析脚本。A 为只显示命令的基础确认界面，B 为 Airlock 影响/diff 界面。实验全部使用合成沙箱任务，不让真人误操作真实资源。

任务必须给出业务目标和真实授权背景，否则“该不该批准”没有可靠金标。用经过独立确认的可接受决策集合判分；随机分组，或采用反平衡的被试内设计，避免同一人看过答案后再做完全相同任务。记录熟悉度、难度、顺序、后台停留与退出，不把同一人的多次点击当多个独立参与者。

- **H1**｜平均决策耗时目标 ≤5s；“3 秒看懂”是更强的待验证设计假设，不能自动当达标。并报中位数/p95、样本量及置信区间，确保计时遵循 C7.5。
- **H2**｜决策正确率目标 ≥90%，参照真实任务授权金标；连同危险误批、合法误拒、请求更多信息等行为分析，不能只奖励拒绝所有操作。
- **H3**｜原称“橡皮图章率”的 <1s 批准占比目标 <5%。本轮称“快速批准代理指标”，明确分母；它是风险观察信号，不单独证明敷衍、理解或因果。结合正确率和简短理解核验解释。
- **H4**｜原批量只读归并目标 ≥80%。预注册 eligible 请求、原始通知/审批数和显示组数的口径；把只读免审、幂等重复抑制与真正归并分别测量。基线审批数为 0 时不能除零或制造改善百分比。
- **H5**｜日均审批次数目标 <20 次。必须绑定可复现工作负载、活跃用户天、任务完成量和质量；无真实使用天数则该目标未验证，不能由短脚本外推“每天”。

真实参与者建议先做 n≈12 的探索性试验，但这不是已有人数或充分统计功效保证。必须报告实际 n、每人任务数、缺失/退出和配对/分层分析。没有真人时 n=0，交付可运行试验工具、招募/同意说明、匿名数据模板和分析入口；真人效果保持 BLOCKED_EXTERNAL。

禁止写入旧示例结果“11.4s→2.8s、74%→93%、31%→4%（n=12）”作为已发生事实。这组数字仅是原文格式示范。

## 9. L3 红队与安全回归

只测试自己拥有且为此建立的隔离环境。每个反例保存前置条件、请求、目标状态前后、动作终态、审计和复现命令。

- **R1**｜绕过代理直连：验证 Agent 不能访问目标数据库/卷、服务端配置、reviewer/audit 凭据、Docker socket、宿主能力或受保护上游。检查真实 Docker 网络、运行身份、只读根、能力位和入口；只看 compose.yaml 不算完成。在声明的部署模型内此项零失败，不能声称可抵抗已控制宿主/root 的对手。
- **R2**｜参数与解析混淆：覆盖多语句、注释、大小写、Unicode、CTE、RETURNING、ATTACH、系统表、扩展、DDL/触发器、NaN/Infinity、大整数、二进制、重复列名和资源耗尽；依据具体 SQL 方言判断是否合法，不假设 DR\"\"OP 在所有数据库中都等同 DROP。边界内解析与授权必须一致。
- **R3**｜提示注入：在 SQL、工具描述、资源内容、模型输出和拒绝建议中嵌入伪系统指令、批准指令和输出欺骗；确保它们只是数据，不改变身份、政策、审批或执行控制。
- **R4**｜伪造审批与替换：覆盖 Agent 伪装 reviewer、跨 action/reviewer/资源/权限范围替换、请求或摘要改写、过期/撤销、重放、SSE 伪造和并发竞争。声明支持范围内未授权批准/执行必须零失败。
- **R5**｜降级滥用：模型/预演失败、低风险拆单、并发预算耗尽、重复提交、历史批准投毒、批量组加入隐藏成员或路由失败不能让请求获得额外权限；不可逆/高危操作通过学习自动降级必须零发生。
- **R6**｜拒绝与证据泄露：检查错误、日志、SSE、指标、审计与 UI 导出不泄露密钥、敏感样本或可用于越权的细节；错误响应本身可序列化，不直接回显危险输入。结合已有用例补授权检查、XSS/CSRF/SSRF 等适用风险。

任何未授权副作用、审批对象可替换或不可接受的业务/审计提交不一致定为 P0。核心流程不能启动、关键队列不可见、必需测试假绿等为 P1。P0/P1 先最小复现，再定点修复、增加回归和全套复验。测试可以重构，但必须证明覆盖等价或更强，不能删减来凑通过。

## 10. L4 生态、演示、技术栈偏差与交付目标

- **E1**｜生态数据：记录实际日期的 star/fork/真实外部贡献和被集成证据；暂无采用就是暂无，不购买、不伪造、不把自己的测试调用算外部集成。
- **E2**｜上游参考实现：核查原文“Envoy/agent-router #2073”的准确仓库、issue 内容、日期和当前状态；未经验证不沿用引用。准备可复现示例和礼貌的 issue/PR 草稿，但未获用户授权不向第三方自动发帖，也不声称已经被采纳。
- **E3**｜演示与事故区分：保留 1206 行合成数据的“无代理/有代理”对照及拒绝/批准闭环。无代理演示只在独立一次性数据库，不能关闭正式安全保护去操作其他数据；没有事故完整证据链时叫“受事故启发的演示”，不叫精确复原。
- **E4**｜研究事实：重新核对 Replit/AI Incident Database #1152 的数字与叙事，以及 LlamaFirewall、MCPGuard、AgentTrust、agentgateway、mcp-firewall、Docker、Cloudflare 等原文比较；只用可核查的一手资料支撑结论。不能凭名字或某个旧 issue 推断别人现在全都没有审批 UI/路由/疲劳治理。
- **D1**｜技术栈偏差：原始简报曾提出 FastAPI＋Next.js，当前是 FastAPI＋原生 JavaScript/CSS。单列偏差和影响，不冒称已用 Next.js/Vue。先保住安全与完整交互；框架迁移作为独立变更提出理由和迁移验证，不因过去 npm 受限就永久声称目标已满足。未确认的框架差异保持未关闭，不擅自伪造用户同意。
- **D2**｜开发与运行材料：README、架构/状态机图、API/数据模型/策略契约、威胁模型、启动配置、依赖锁定或明确版本、测试/演示命令、使用手册与故障排查同步最终实现；不只交付接口或只交付静态前端。
- **D3**｜简历与面试包：更新项目定位、真实贡献说明、可核查简历条目及标准问答，至少涵盖授权、TOCTOU、幂等、事务/远端未知、MCP、CEL、LLM 角色、审批疲劳、实验、审计和失败修复。新增功能未实现就不能写入“已完成能力”；禁止只堆测试数量。
- **D4**｜成果提交和持久证据：代码、测试、配置、目标矩阵、问题修复记录、验收结论与进度进入仓库。原始证据区分 Git 跟踪文件、Actions artifact、release/其他已授权归档及本地文件；未永久保存的日志/截图不能说已全部提交。检查脱敏、体积、授权和保留期，不提交密钥、运行库或字体文件。

## 11. Kill Criteria 与执行纪律

这些是原始预警线，不是看到失败就私自删功能、改指标或关闭安全控制的授权。触发时记录证据、影响及建议，核心安全失败先修复。

- **K1**｜危险召回反复调优仍 <80%：记录失败类别，提出收窄适配范围/场景重做的方案；不得在未经确认时删目标后宣称全量完成。
- **K2**｜FPR >25%：分析合法请求被打扰原因，改进规则和路由；原建议“只管不可逆”不能直接拿来放开原需审批的写操作。
- **K3**｜决策耗时 >15s：检查信息设计和任务难度，重做 C7 的相关部分并以同口径复测。
- **K4**｜快速批准代理指标 >20%：结合正确率、理解核验与任务复杂度判断；不机械归因为用户敷衍，检查 C8 治理是否有效。
- **K5**｜声明的保护边界可绕过：架构级失败，停止相关危险扩展，修复边界再重测，不允许靠 README 警告代替已承诺的控制。
- **K6**｜dry-run 覆盖率 <30%：明确分母和不支持类型，提出改进适配器或诚实收窄支持范围；不能自动切成“让 LLM 猜影响并获准执行”。

- **W1**｜评测从本轮开始：先梳理/冻结数据和标注缺口，不能所有实现完成后才发现无法衡量；真实来源缺失立即登记，继续离线可完成工作。
- **W2**｜优先真实闭环：每个阶段能被独立运行和复验，再逐步扩展；不先堆抽象/大框架或用 mock 取代验收。
- **W3**｜持续演示与进度：每个有实质变化的阶段保存简短演示录屏/GIF或等价证据，能录时以约 30 秒为参考；不伪造已经每周录制的历史。同步 memory/progress，所有展示数字只用真实结果。

## 12. 分阶段实施，不把“完成计划”当“完成项目”

### 阶段一：原状审查与目标建账

核对工作区和远端，创建完整目标矩阵。审查测试脚本是否安全，先在隔离合成环境跑原有基线；形成代码变更前的审查结果。逐条识别“缺陷”“缺功能”“缺验证”“设计偏差”，不要全部混成 bug。

### 阶段二：核心 P0/P1 与不可退化门禁

优先 A1—A4、L0、R1—R6，以及 pending 分页、非法输入、真实退出码和 Docker 网络等历史问题。每个修复由最小复现支撑，回归应尽可能证明修复前失败、修复后通过。

### 阶段三：原功能补齐

按依赖增量推进 C1/C2/C3/C4/C5/C6/C8/C12 的缺项，同步 C7/C9/C10。建议先策略/数据契约和受控适配器，再路由/分组/预算，再可选模型与观测；可根据真实依赖调整次序，但不得删除目标。对于新增远端副作用，先证明审批绑定与结果未知语义，再启用执行。

### 阶段四：独立反例、评测和体验工具

执行 C11、T1—T6、B1—B8 和 H1—H5。补齐离线可运行实验工具，运行被授权的真实模型集成。外部数据/人员/预算缺失按对应项目受阻处理，不能让它掩盖其他可实现代码缺口。

### 阶段五：冻结与交付

冻结待测提交，完整复验可执行路径，保存证据；更新研究、面试、运行说明和跨会话记录。最终给两份清楚的结论：当前已声明且已测实现是否通过；最初完整目标是否全部满足。后者不能被前者替代。

最小破坏演练只能使用带唯一前缀的临时数据库、容器、网络和卷，验证清理操作只作用于本次创建资源；禁止全局 docker prune、删除用户分支/目录或接生产数据库。

## 14. 状态、证据和最终报告格式

### 14.1 每个目标的记录结构

创建 `docs/acceptance/COMPLETION_MATRIX.md` 及同内容的 JSON。覆盖 G1—G4、A1—A4、C1—C12 及全部子项、L0-1—L0-7、T1—T6、B1—B8、H1—H5、R1—R6、E1—E4、D1—D4、K1—K6、W1—W3。配套 JSON 只用于核对 ID 完整性，不能作为被测业务的正确性 oracle。增加矩阵结构检查：目标 ID 缺失/重复、未定义状态或 PASS 缺少证据关联时失败；该检查通过本身不证明功能通过。

每条至少包含：

```text
id
原始目标/本轮明确的验收标准
要求来源（原始目标 / 安全修正 / 为原目标补充的可测试定义）
实现状态（MISSING / PARTIAL / IMPLEMENTED）
验证状态（NOT_RUN / PASS / FAIL / BLOCKED_ENV / BLOCKED_EXTERNAL）
适用范围与未覆盖范围
代码路径与必要行号或符号
测试 ID、命令、退出码、原始证据路径
tested_commit_sha、数据/配置/模型/策略版本
实际结果（无结果用 null，不填目标值）
修复记录与剩余问题
阻塞原因、解阻所需最小输入和复验命令
是否涉及安全修正/原目标偏差及用户确认记录
```

“部分完成”属于实现状态，不与 PASS 混用。BLOCKED_ENV 是具体环境能力缺失；BLOCKED_EXTERNAL 是授权凭据/预算、真实用户数据或人员等缺失。NOT_RUN 说明尚未运行，不能假装环境阻塞。真实运行但行为不符是 FAIL，不因难修变成未验证。

父 C 项只有所需子项、实际支持范围和必需端到端测试全部满足才能声称该能力完整通过。范围外部分仍要在原目标矩阵暴露。没有必要也不要计算模糊的“完成度 95%”；报告具体已通过、失败、缺失和受阻的数量及 ID。

### 14.2 修复与证据

创建 `docs/acceptance/FINDINGS_AND_FIXES.md`，每项记录严重度、最小复现、修复前结果、根因、修复位置、修复后回归和剩余风险。

创建 `docs/acceptance/FINAL_REPORT.md`，结论不能只写“全部通过”，必须分别包含：

1. 原始完整目标的达成情况与未满足 ID。
2. 当前已实现范围的功能/安全/集成验收结论。
3. 真实模型、真人效果、真实来源数据和生态采用的单独状态。
4. 本轮实际改动、版本和可运行演示入口。
5. 测试及证据的对应位置、存储形式、保留期限。
6. 本地提交、远端分支、PR、main 是否合并的各自实际状态。

在 `evidence/<run-id>/` 或等价唯一目录保存日志、JUnit、逐样例结果、脱敏追踪、截图、命令退出码、环境信息和哈希。manifest 只能索引证据，必须独立核对必需文件内容、测试结果和哈希；缺任何关键产物不能因“有一个 JSON 报告”就通过。

验收绑定实际 tested_commit_sha。提交报告产生新文档提交时，说明它与被测代码提交的关系；之后若有可执行代码/配置/依赖变更必须重跑相关检查和最终门禁，不把旧 SHA 的成功挪给新代码。保留依赖 warning 和已知限制，不统一屏蔽。

## 15. Git 提交与 memory/progress 更新

代码修复和新增功能按清晰主题小步提交到本轮工作分支。保留用户工作，提交前检查密钥/个人数据/运行库/大文件；提交说明如实描述，不用“fully complete”掩盖未实现项。

有授权的远端写权限时推送本轮工作分支；通过现有项目方式提交待合并变更，未明确授权不擅自绕过保护合并 main。没有远端写权限时交付本地 commit 与补丁，明确“未推送”，不能口头说仓库已更新。

更新 `memory/progress` 时使用独立 worktree 或等价安全方式，先读最新版本并保留历史，避免切换脏工作区或覆盖并行修改。至少更新：

- PROGRESS.md：本轮实际完成、缺项、失败、受阻和下一步。
- STATE.json：actual_main_sha、working_branch、working_commit、tested_commit、CI/证据及远端同步状态；不能把工作分支 SHA 填成 main。
- 本轮目标矩阵/报告的路径与最新已测试代码链接或提交定位。

不把本次大量实现代码灌进仅记录进度的分支。若不能安全更新记忆分支，将待写入内容保存到工作分支并标明未同步。发生远端冲突时拉取对照后合并记录，不能 force-push 消灭别人的更新。

### 交付停止条件

可安全执行且已授权的检查、修复、增量实现应尽可能完成；不能仅因任务长就把所有缺项推给用户。由于真实权限、外部人员或当前执行环境无法继续的项，要有明确证据和可接续方案。

只有全目标确实满足才能说“原规划全部完成”。存在功能缺项就说“部分实现”；只有代码完成但 live/human 等未验证，就说“代码侧已完成，外部效果待验”；存在 P0/P1 就不能给通过结论。全部输出使用中文，文件名、代码标识和必要协议术语保留原文。

现在开始执行：先核对真实基线和目标矩阵，随后进入检查、修复及可实施缺项的补齐，不停留在阅读或建议阶段。
