# 实际演示与源码阅读

## 场景A：一条真实审批闭环

启动新环境，登录后点“新建演示请求”→“创建待审批请求”。页面应展示6条测试客户标签变化，直接影响6、级联0、恢复未配置。未填写理由不能批准。翻页查看全部6条，填写理由并批准。先变为可执行/执行中，最后显示执行完成及回执。

在“审计记录”中查看原操作和当时视图；历史JSON来自保存快照而非重算。第二次用相同演示参数可能为零变化，不能把它当新的6条业务效果。每次独立演示使用新初始化目录，而非开放清库接口。

## 场景B：宽范围操作被阻止

点“运行阻断场景”。合成库有1206客户、24条级联备注，总影响1230条。应显示BLOCKED，不存在批准按钮。1206是可复现fixture规模，不是取到真实事故原始数据库。

## 场景C：级联可见、人可拒绝

“检查级联删除”匹配前6个测试客户、12条备注，总18条。逐项展开diff，填写理由拒绝。客户和备注不会被删除。拒绝理由由后端返回Agent，Agent只能提出新方案，不可把自己说的“用户已批准”当授权。

## 场景D：状态漂移和崩溃恢复

自动化证据更可靠：

```bash
python -m pytest -q -s tests/test_target.py::test_stale_target_blocks_even_same_row_count
python -m pytest -q -s tests/test_process_recovery.py
python -m pytest -q -s tests/test_mcp_live.py
```

状态漂移测试会在预检后通过独立测试写入改变目标，即使行数不变，旧计划也不执行。崩溃测试在目标提交后用 `os._exit(88)` 终止真实Python进程，再启动新进程，只通过事务回执恢复成功且回执数量1。测试故障点只存在tests，不是生产HTTP后门。

MCP测试启动真实stdio server/client和两套HTTP进程，验证tools/list、授权查询、待审批→独立批准→真实6行变更。它不调用大模型，不掩盖这一点。

## 最值得逐行理解的文件

- `contracts.py`、`config.py`：参数与身份权限如何成为强制规则。
- `target.py`：backup影子、全量主键diff、事务内复核、回执原子提交。
- `plans.py`：无环摘要与签名范围。
- `service.py`：任务领取、不可变审批、撤权、UNKNOWN核实、并发。
- `auth.py`、`http_security.py`：独立身份、CSRF、限速和输出边界。
- `ReviewDetail.vue`、`workbench.ts`：真实diff、状态恢复、按钮可用性、分页与可见性埋点。
