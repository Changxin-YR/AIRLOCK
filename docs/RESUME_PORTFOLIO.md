## 可用于简历的项目条目

**AIRLOCK｜Agent 工具调用审批与影响预演（个人项目）**  
Python、FastAPI、SQLite、CEL/YAML、MCP、Next.js、GitHub Actions

- 实现 HTTP/MCP 接入的服务端审批核心，将 Agent 调用身份与审核身份隔离，支持三态策略、持久化审批及结构化拒绝后的安全改道。
- 基于受限数据快照生成影响数量与字段 diff，将请求、策略、TTL 和数据指纹绑定；通过事务内复核、幂等键及业务效果/状态/审计同库提交处理重复请求、状态漂移和提交前崩溃。
- 构建审批台及故障反例测试，覆盖官方 MCP SDK、原生浏览器和隔离 Docker；已核验版本通过 687 项 Python、6 项 JavaScript 测试及 31 项浏览器检查，原始日志、退出码和源码提交可追溯。

若版面有限，保留前两条，把测试覆盖融入第二条末尾。测试数量是固定验收版本的证据，不是性能、安全认证或本人已熟练掌握的证明。当前缺少真实业务效果研究，因此简历不填写召回率、审批效率提升或生产用户规模。

## 一分钟介绍

“AIRLOCK 是一个个人 Agent 工具调用审批项目。我关注的是：人批准的操作，是否就是最后被执行的操作。Agent 只提交意图，服务端先预演影响，在审批界面展示数量和 diff；批准时再次核对请求、策略、版本和数据状态。本地数据修改、动作终态与审计在同一事务提交；远端响应丢失则进入 unknown，通过原收据对账。项目用合成数据验证正常、拒绝、并发和崩溃路径。真实业务效果和生产部署尚未作为已完成成果。”

## 五分钟演示顺序

| 时间 | 操作与画面 | 要解释的工程点 |
|---|---|---|
| 0:00—0:45 | 展示 Agent → Gate → reviewer → 目标的流程 | 执行权与凭据隔离；同一高权限开发目录不等于隔离部署 |
| 0:45—1:45 | 提交删除合成记录，审批台显示 pending 和影响 1206 行 | pending 没有业务效果，diff 是送审信息 |
| 1:45—2:30 | 拒绝；模拟 Agent 改为 SELECT，仍有 1206 行 | 拒绝后安全改道，不能换键重试相同写入 |
| 2:30—3:30 | 新建 `id=1` 的余额更新，核对 diff 后明确批准 | 只对批准的快照执行；读回结果与审计 |
| 3:30—4:30 | 打开幂等、漂移、审计失败或进程退出测试及其收据 | 解释一个真正的失败窗口与修复依据 |
| 4:30—5:00 | 展示 CI 原始证据与范围说明 | 区分合成回归、真实协议互通与真人业务效果 |

演示环境使用全新合成库。按 [README 本地演示](../README.md#本地演示)准备依赖；在新的操作者 PowerShell 中创建独立配置和数据库路径：

```powershell
$resumeDemo = Join-Path (Get-Location) ('var/resume-demo-' + [guid]::NewGuid().ToString('N'))
$env:AIRLOCK_DB = Join-Path $resumeDemo 'demo.sqlite'
.\.venv\Scripts\python.exe -m airlock init --config (Join-Path $resumeDemo 'local.json')
.\.venv\Scripts\python.exe -m airlock serve --config (Join-Path $resumeDemo 'local.json')
```

端口 8000 需空闲。操作者本人只在本机查看新配置，将 reviewer token 输入审批台；模拟 Agent 使用另一终端，只获得 agent token。凭据不贴到聊天或提交 Git。调用 `scripts/demo_agent.py --scenario delete` 并在页面拒绝，然后调用 `--scenario update` 并核对后批准。结束用 Ctrl+C 停止本次服务，保留该库用于审计；重复演示创建新路径。
