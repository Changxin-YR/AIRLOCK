# 威胁模型与保证边界

## 保护对象和攻击者

保护固定合成 customers 表的写权限与审批对象的一致性。攻击者可以控制 Agent 的 SQL、参数、HTTP/MCP 调用、重试/并发、额外 JSON 字段与提示注入文本；不能取得服务器进程、数据卷、reviewer/audit 密钥、Docker socket、宿主 root 或代码修改权。

把整个开发目录交给具有 shell 的 Agent 会违反这个前提；即使正常工具经过代理，Agent 若仍可直接读写数据库文件，代理也不能保证控制。开发者本人掌握部署权限，不在该威胁模型内。

## 防线

严格输入模型与固定角色；表/函数/动作白名单；限额与执行预算；无批准不写；私有克隆预演；参数/版本/TTL/策略/数据指纹绑定；写锁内再校验；同库原子效果与审计；幂等和冲突；HMAC原始快照；前端文本渲染与内存凭据。模型提供的“安全”标签和客户端 approval 字段没有授权效力。

独立测试应直接验证目标行、终态和审计三者，不能只断言 HTTP 200。Docker smoke 使用唯一临时 project 与测试卷，检查 Agent 的非 root、只读文件系统、零能力位、无服务器卷和敏感环境变量，以及 API 拒绝伪造审批；只清理本脚本新建的项目。

## 证据不等于过度承诺

原生浏览器流程通过仅证明已测工作流和渲染，没有覆盖所有浏览器、辅助技术、CSP 绕过或 XSS。Docker smoke 不是通用容器逃逸/网络渗透评估。自动化测试中的 reviewer 是测试代码，不是真人参与者。

CI图标也不是充分证据。项目在第二轮运行中发现日志管道掩盖 Docker 失败，已经将它列入已知失败历史。后续必须检查实际子命令退出码、JUnit必需测试、Docker/native报告和原始日志。不要删除失败历史制造一次全绿的叙述。

## 不在本版保障内

没有真实模型的行为评估、SSO/MFA、审批人生命周期、多人职责分离、多租户/列级敏感数据权限、生产数据库连接器、备份恢复、自动降级或任意Shell沙箱。

固定白名单表内读取刻意允许；不能连接真实客户资料并声称防数据外泄。合成回归标签不能当真实世界危险操作金标。

HMAC无外部锚定，无法证明尾部未被截断或管理员没有拿到签名密钥。TTL依赖可信服务器时钟，重大回拨属于运营故障。速率/容量限制只是小项目资源保护，不是抗DDoS平台；没有归档生命周期。

远端SQL、邮件、文件或支付不能共用当前单库原子性证明，需下游幂等收据、结果查询、Outbox/补偿和人工处置 unknown 状态。公网使用前还需要 HTTPS、身份/授权系统、密钥与网络管理、依赖审计、监控与独立安全复核。

## 验收顺序

先核对当前 main SHA 与记忆分支；再执行测试和真实原生浏览器；最后在一次性部署中验证隔离与重启持久性。用实际报告区分 PASS、FAIL、NOT RUN、ENVIRONMENT BLOCKED。未执行项不自动降级为通过。
